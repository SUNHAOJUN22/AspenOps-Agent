# Contributing

1. Create a focused branch.
2. Add deterministic Mock tests before real Aspen experiments.
3. Run the full quality gate in `AGENTS.md`.
4. State whether a change was tested on a real licensed Aspen installation.
5. Never commit proprietary cases or vendor material.

Pull requests that add capabilities must update the corresponding architecture, security or numerical documentation and must not expand the MCP attack surface without explicit policy and tests.
